# 矩形原生覆盖与 GPU 软裁剪

Status: accepted（2026-10-31），[决策：正式验收拒绝硬边后的矩形覆盖与软裁剪修复路线](https://github.com/shuizhongyueming/canvas2d-webgl/issues/81)。本决定修订 ADR-0001 的二值模板裁剪与矩形快路，不改变 WebGL 1、持久场景纹理及素材级原生辅助的边界。

正式矩阵 `1a59f24` / `a913af34-754b-493a-930a-8fb1607ed312` 中，小数矩形、旋转矩形、旋转清除、曲线裁剪均丢失原生部分覆盖。兼容侧边缘 alpha 只有 0/255。四项最大 alpha 差分别为 128、126、104、128。用户要求修复后重新验收。历史决策 #43/#52 只允许待评审合并，不能作为最终像素接受记录。

## 决定

- 轴对齐且设备边缘为整数的纯色矩形保留 GPU quad。其他填充使用原生 `fillRect` 生成局部素材。矩形描边使用对应的原生 `strokeRect` 素材，不用 `rect()+stroke()` 替代；软件光栅的后者会漏掉细小矩形的外角覆盖（人工复核 `rect.clearRect.path-independence` 反例）。
- 非整数/旋转清除使用原生白色覆盖素材。GPU 以 `D*(1-C)` 衰减预乘目标颜色及 alpha。paint、globalAlpha、filter、合成模式不参与清除。
- 原生按快照从根到叶重放整条 clip 链，再生成有效覆盖纹理。同一路径快照和规则的重复裁剪按交集幂等去重，避免软件 Skia 重复衰减而默认 GPU 画布保留边缘的后端差异。不能把各级独立抗锯齿遮罩直接相乘，否则重复裁剪会错误地稀释边缘。GPU 在设备坐标采样这张软覆盖纹理，不再用 0.5 阈值截断 alpha。
- source-over、source-atop 在源合成前乘裁剪覆盖。对公开差分的默认原生 GPU 画布，lighter 先执行饱和加法，再按裁剪覆盖与原目标混合，因此也保存当次原目标纹理。软件 Skia 在此可能采用不同顺序；内部软件微实验不能替代公开原生参考。
- 有裁剪的 source-in 单独计算 `D*(1-C) + S*Da*C`。先以临时 GPU 纹理保存原目标 alpha，再衰减整个有效裁剪中的目标，最后加入源贡献。源外透明区域仍须影响有效裁剪。临时纹理分配/复制完成前不修改场景；当次调用的 finally 删除临时纹理并释放遮罩/源租约。
- 无裁剪的 source-in 保留既有 stencil 三遍方案。为避免同时扩大错误/资源契约，普通 clip 255 级、source-in 254 级上限继续有效。

## 代价与边界

软裁剪增加遮罩上传与纹理采样。裁剪内 source-in / lighter 增加一次原目标 GPU 复制，source-in 另增加绘制次数。部分矩形增加原生光栅与上传成本。首版优先正确性，本决定不承诺性能。

没有双 FBO ping-pong，没有主场景原生回退，没有新公开 API，没有放宽差分断言或容差。原生参考仍使用公开原生画布配置；内部素材配置不决定公开差分是否接受。

## 验证

真实浏览器断言部分边缘覆盖存在，检查软裁剪与四种合成模式、重复裁剪、源外清除及 restore。既有矩阵继续检查 alpha/filter、嵌套/空裁剪、动态源、尺寸重置、lost/restore/dispose 和资源清理。所有原生/兼容 scene 与 display 对仍需独立评审。

修复提交从干净工作区重新采集完整矩阵。旧提交的人工或 AI 记录不得迁移到新 commit/sourceHash/artifactHash。此决定只批准方案，不签署验收。

实测补充：同一半像素 clip 和半透明 lighter，默认 GPU 原生边缘为 `[229,27,0,223]`，`willReadFrequently` 软件画布为 `[216,24,0,255]`。这修正了方案初稿将软件实验外推为默认画布行为的假设。公开差分保留默认原生配置，按实际 GPU 参考验证，不更换参考以消除差异。
