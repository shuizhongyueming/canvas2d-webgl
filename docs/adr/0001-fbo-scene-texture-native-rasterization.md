# FBO 场景纹理持久化与原生光栅化分工

Status: accepted（2026-10-16，决策过程见 GitHub issue #5）

兼容画布的渲染由两条互锁的架构决策构成：

1. **画布内容持久化在库自建的 WebGL 帧缓冲（场景纹理）**，每个提交点（当前任务的微任务检查点）一次性 blit 上屏，而不是 `preserveDrawingBuffer: true` 直绘默认帧缓冲。原因：Canvas 2D 的跨帧保留语义必须由库自己精确掌控，`preserveDrawingBuffer` 的行为在小游戏平台上参差，且 FBO 为将来的读回与差分测试钩子留出稳定的取样面。代价：一块 `宽×高×4` 的显存和每提交点一次全屏 blit。

2. **路径填充/描边与文字统一经内部原生离屏 2D 光栅化为纹理再合成**，首版不做 CPU 三角化。原因：差分验收的参考渲染就是原生光栅器，同一路径走同一光栅器可把边缘与抗锯齿分歧降到接近零；这是素材级辅助而非整帧上传，不违反「主场景 WebGL 渲染」的要求。代价：每帧大量独特路径时的栅格化与纹理上传开销（样例游戏的伪 3D 挤出即此类）；首版性能明确不在验收范围。

## Considered Options

- `preserveDrawingBuffer: true` 直绘默认帧缓冲：结构更简单、省显存，但保留语义交给平台实现，且阻断读回/测试钩子。
- 命令重放：内存随绘制历史无界增长。
- CPU 三角化（earcut 类）：免纹理上传，但 evenodd、自交、描边连接的正确性难保证，且两套光栅器的 AA 差异会贯穿差分测试。
- 凸四边形直通 WebGL、其余走原生光栅化的混合路线：留作将来性能工作的首选方向，但需先评估两套光栅器边缘差异对差分容差的影响。

## Consequences

- 外部 canvas 作为 `drawImage` 源时每次调用重新上传当前内容，无跨调用缓存——「不接管外部 canvas」的直接落实。
- `createPattern(image, "repeat")` 用 shader `fract()` 平铺，规避 WebGL 1 对 NPOT 纹理的 REPEAT 禁令。
- 上下文恢复时丢弃全部内部缓存并重建 GL 对象，场景纹理清为透明黑，外部源不做保留。
- 裁剪走模板缓冲（evenodd 用绕数通道），四种合成模式映射为预乘 alpha 的 GL 混合，`brightness(120%)` 在片元 shader 做颜色矩阵。
