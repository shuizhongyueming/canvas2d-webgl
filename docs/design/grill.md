## 已确认输入

1. 输入 HTMLCanvasElement，内部基于其 WebGL 渲染。
2. 返回模拟 HTMLCanvasElement，外部仅通过 getContext('2d') 获取绘图上下文。

4. 需要完备的差分测试架构：原生 2D 与兼容层运行同一用例，误差须在合理范围。
5. 样例游戏：gc-2026/packages/unknown-epic-rage/src/app.js。

## 第一轮：已回答（全部接受建议）

## 最终设计（用户已于 2026-10-16 确认）

### 库的使用边界

输入尚未绑定上下文的 HTMLCanvasElement 或平台对应画布，返回游戏可用的兼容画布对象。目标画布由库独占，内部以 WebGL 1 为最低基线渲染。外部通过 getContext('2d') 使用，普通绘制不需要显式 flush/present。返回对象不保证真实 DOM 元素身份。

通过兼容画布设置宽高会遵守 Canvas2D 清屏、状态重置语义。平台无法完成的尺寸操作明确报告。首版不支持任何以兼容画布为 drawImage 图像源的调用。

### 混合渲染

注入的原生离屏 canvas 工厂仅供库内部使用，文字、测量和辅助素材可复用原生 2D。主场景使用 WebGL，整帧原生 2D 绘制后上传不是默认实现。内部原生 canvas 的修改由库自身管理；不接管外部游戏创建的 canvas，但外部 canvas 被传入 drawImage 时刷新内容并保持取样顺序，调用方不必手动标脏。

### 首版兼容范围

以 unknown-epic-rage/src/app.js 使用到的绘图 API 及组合语义作为必须通过的范围。包含图像、矩形、状态与变换、路径填充/描边、裁剪（含 evenodd）、重复纹理、线性渐变、实际用到的合成模式、brightness 滤镜和文字绘制/测量。运行时覆盖仍需验证，不能以静态扫描代替场景验收。未覆盖能力明确报告，不做静默空实现。

### 测试

语义测试与像素差分并行，覆盖单接口、组合、尺寸重置、跨帧以及外部离屏源修改顺序。每次测试在当前环境同时执行原生 2D 与兼容实现，不使用持久化参考截图基线；固定相同用例输入，文字两条路径使用同一已加载字体。

不强制锁定本地运行环境。每个支持环境分别与其原生结果比较，不要求跨环境逐像素一致。结合误差幅度、超阈像素比例与局部差异区分内部像素、边缘和文字；具体阈值在基线实验后确定。记录环境和失败用例，输出参考图、实际图、差异图。首版不要求性能基准或性能准入。

### 生命周期

提供库级 dispose，释放库拥有的资源与调度，不销毁传入目标画布。上下文丢失时暂停并通知；恢复时重建资源、清屏并通知重绘，不保证历史像素恢复。
