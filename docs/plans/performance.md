# 游戏性能优化与复测

2026-11-02；跟进 [真实游戏性能](https://github.com/shuizhongyueming/canvas2d-webgl/issues/85)。用户将目标明确为：保持渲染一致性，最低30FPS，期望60FPS。本任务扩展历史首版计划中排除性能的范围。

## 验收口径

先在同一台机器、同一个硬件GPU后端、相同主画布尺寸上，顺序运行原生和兼容模式。每种模式使用独立浏览器上下文。不得并行运行性能测试和浏览器回归，也不得降低分辨率、删绘制、改游戏计时或使用原生回退来达标。

默认样本为 Epic Rage 的 `afg#bee`、390×844 CSS视口、DPR2，实际主画布850×1839。另测1280×720桌面视口。具体尺寸必须以报告的application.renderer字段为准。设备或游戏场景变化后需要重新测量；一次开局样本不能证明所有设备和关卡均达标。

每次预热3秒、采样10秒，至少重复3轮。记录平均FPS和帧间隔p50/p95/p99/max，并观察物理时间是否接近墙钟时间。30FPS预算33.33ms，60FPS预算16.67ms。基准脚本将平均FPS≥目标且p95帧间隔≤预算+0.5ms作为性能检查；0.5ms仅处理rAF时间戳量化，不是图像差异容差。绘制回调耗时不含全部微任务提交，不能代替帧间隔。

```sh
node scripts/benchmark.mjs --url http://127.0.0.1:8084/index.html --adapter <仓外适配器.mjs> --output test-results/performance-85/run-1
node scripts/benchmark.mjs --url http://127.0.0.1:8084/index.html --adapter <仓外适配器.mjs> --width 1280 --height 720 --dpr 1 --output test-results/performance-85/desktop-1
```

前提：在游戏仓库启动用户授权的 `afg#bee` 开发环境，游戏通过本地link加载当前库构建，服务为8084。游戏资源不随本公开库分发。基准默认请求Metal，报告必须显示实际GPU。`--software`仅作诊断，不能用于宣称硬件帧率通过。脚本返回1表示失败或软件后端，0表示本次所选样本满足检查，不等于整个项目验收完成。

## 实现边界

场景继续保存在WebGL FBO。路径、文字、矩形软覆盖和裁剪仍使用既定原生光栅器，没有新增三角化或整帧原生渲染。

- 保留场景原点和尺寸，仅清理本次读回窗口；避免每个小路径清空整张原生画布。
- 路径、矩形和裁剪优先保留原生ImageData。GPU可直接消费；仅原生测试消费者需要时才生成第二张素材画布。
- 每个Canvas调用同步捕获来源当前内容。内部批次最多256项，素材图集最多2048×2048。图集是独立素材的存储空间，不是主场景的原生合成结果。
- 外部图片/画布每次重新捕获，没有来源内容缓存、脏标记或属性拦截。只捕获采样窗口及双线性邻域。通过顶点UV、逐项滤波和窗口夹取避免相邻素材污染。
- GPU按原始调用顺序执行各项变换、透明度、合成、软裁剪和filter。内部读回先提交待处理项。容量不足、超大来源或清除操作可提前提交。
- 复用有界上传纹理。显式租约、上传缓冲和裁剪缓冲分别在测试计数里呈现。resize/loss/dispose丢弃旧批次和GPU缓冲；dispose释放原生图集与安全探测画布。

参数、尺寸限制、跨域检查仍在调用时报告。跨域探测在1×1原生画布上复制一个源像素，再读取画布外的透明像素；origin-clean检查仍执行，避免GPU读回。真实跨域图片和污染canvas均必须同步抛SecurityError，之后合法来源必须仍可绘制。

批次的显存分配和GL执行错误在执行批次、内部读回或微任务提交点显式报告。受控更新不再每个素材都做一次同步getError。提交失败拒绝whenPresented等待者，并保留可见错误；不能静默回退或挂住等待者。这改变内部错误观察阶段，审阅时需同时检查调度和资源测试。

## 一致性和回归

- 工程检查、完整浏览器语义和组合用例必须通过。重点覆盖同任务来源修改/resize、超过256项的批次边界、alpha/filter/合成/软裁剪、读回、窗口reset、真实loss/restore、跨域污染后的恢复。
- 将161项旧实际画面与优化后的实际画面逐像素比较，记录所有变化。数值差异不自动接受，不新增渲染容差，不沿用旧人工签署绑定新提交。
- 真实游戏用ego-browser比较开局自然下落、持续输入、战斗、换装、结算、缩放和丢失恢复。测量时仅运行单实例；对照截图不证明帧率达标。
- #85在性能和一致性证据齐备前保持开放；#58的正式七场景证据及双方评审另行处理。

## 基准适配协议

公开库只保留通用驱动。游戏专属适配器、钩子名称和采集代码留在游戏仓库。适配器导出浏览器端无闭包函数 `ready()`、`start()`、`stop()`，可导出Node端 `url(base, mode)` 与 `metadata()`。`stop()` 返回可核对的实际模式（`actualMode` 或 `renderer.mode`），以及采样窗口的 `drawDurations` 数组、实际 `gpu` 字符串、可选 `activityRatio` 和应用状态。驱动独立记录rAF帧间隔；不会用应用回调次数冒充显示帧率。

驱动启动前验证当前dist构建，并记录构建输出hash、适配器hash、应用元数据，以及实际加载JS的URL/响应hash。联调人员仍需重建游戏bundle并核对加载收据；工作区commit本身不能证明浏览器已运行该代码。当前游戏适配器与复测方法在游戏 `docs/performance-benchmark-adapter.mjs` 和 `docs/performance-benchmark.md`。

适配器的应用数据保存在 `application` 内。驱动自己的mode、FPS、帧间隔和错误收据不能被适配器覆盖。实际模式与预期不符直接失败，避免误把原生回退当作WebGL性能达标。
