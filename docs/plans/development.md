# 首版开发实施计划

日期：2026-10-16。状态：计划已制定，尚未开始实施。

## 依据与交付边界

依据[规格](../specs/canvas2d-webgl.md)、[架构决定](../adr/0001-fbo-scene-texture-native-rasterization.md)及[已完成的决策地图](https://github.com/shuizhongyueming/canvas2d-webgl/issues/2)。本计划只分配实施与测试责任，不重新选择架构或扩大 API 支持集。[GitHub 开发计划](https://github.com/shuizhongyueming/canvas2d-webgl/issues/9)的实施子票及原生依赖是领取和进度的唯一入口；本文件保存共同接口、测试策略及并发规则。

交付分两层：Web 首版（完整支持矩阵、语义检查、真实差分评审、七个游戏场景证据）；vivo 1200 接入验证（调用方准备好平台后单独执行）。后者延期不能被记作通过，也不阻塞 Web 层交付。性能基准、优化、发布包和平台接入改造不属于本次计划。

当前只创建计划和实施票，不领取或执行实施票。后续由用户启动 agent 执行。

## 工程约定与第一道门槛

默认采用 JavaScript ESM + JSDoc，公开类型声明单独维护；运行库不依赖 Node 或测试驱动。工程基础票确定可运行的构建/检查命令与浏览器测试驱动，Node 内置测试用于纯逻辑，真实 Chromium WebGL 1 用于浏览器集成。浏览器版本随当前环境，完整记录版本，不沿用临时试写代码或固定截图基线。

基础票合并前，其他实施票不开始编码。其产出必须包括：目录、方法/属性支持清单、错误 code 表、内部数据结构及生命周期接口、测试驱动入口和稳定的测试 ID。它不能为了建立骨架而把未实现的受支持 API 当作成功的空操作。

以下为需要落成代码契约的共同约定；字段的具体 JS 形状由基础票集中落定，不让多个 agent 各自定义。

| 接口/数据 | 必须约定的不变量 | 负责人 |
| --- | --- | --- |
| `createCompatCanvas(target, options)` | 同步、身份稳定、工厂/GL options 检查、不返回半初始化对象 | 公开画布与状态票 |
| `DrawState` | 变换、样式/paint 引用、alpha、合成、filter、文字/描边状态、裁剪引用；提交绘制时捕获快照 | 状态票 |
| `PathSnapshot` | 当前路径独立于 save/restore；记录构造时变换；后续 beginPath/修改不改变已取快照 | 路径光栅化票 |
| `Paint` | solid / linear-gradient / repeat-pattern；对象身份、颜色 stop 更新代数、坐标空间；跨状态恢复不能把可变对象误复制成永久旧值 | 样式票 |
| `RasterSource` | 原生素材源、覆盖范围、设备坐标原点/像素尺寸、alpha/颜色约定、有效期与释放责任；空素材不同于“跳过整个合成” | 光栅化票 |
| 绘制操作 | 一次 Canvas 调用是一次合成单元；包含状态、源、源覆盖范围和有效裁剪；透明区域仍可能影响目标 | GPU/合成票 |
| GPU 设备接口 | 场景 FBO + stencil、资源创建/销毁、尺寸重建、present、lost/restore；所有特性共享此入口而不另建 GL 状态管理 | GPU 票 |
| 资源租约与缓存 | GPU 对象由设备/资源模块持有；素材缓存由光栅化模块管理，paint 更新使关联素材失效；淘汰不得删除正在被当前操作引用的资源 | GPU/光栅化票 |
| 裁剪快照 | 路径、构造时变换、规则、父裁剪引用；状态 restore 可回到先前裁剪；重置清空 | 裁剪票 |
| 调度与 generation | 像素操作按调用顺序写入场景纹理；微任务仅合并 present；resize/dispose/lost 使旧提交回调失效 | GPU/生命周期票 |
| 测试钩子 | 仅测试入口访问场景 FBO 像素、提交完成信号、资源状态；不添加公开 flush/getImageData 或导出能力 | GPU票实现，测试设施票定义消费契约 |

测试中的原生 reference 和兼容 adapter 运行同一绘制脚本。测试钩子只用于观测，不得替代自动上屏测试，也不得让参考路径复用兼容渲染算法。

## 文件归属与集成规则

建议目录如下；工程基础票确定后登记到各实施票。每个特性导出注册函数/处理器，由统一 context 按约定安装，避免所有 agent 编辑一个巨大 context 文件。

| 区域 | 内容/唯一写入责任 |
| --- | --- |
| `src/index.js`, `src/canvas/`, `src/context/` | 创建入口/转发由公开画布票负责，状态/context由状态票负责；前者依赖后者 |
| `src/gpu/`, `src/resources/`, `src/scheduling/` | 设备、FBO、上传、提交、资源注册；GPU票 |
| `src/raster/`, `src/path/` | 原生辅助绘制、路径记录、素材缓存；路径光栅化票 |
| `src/paint/` | 颜色、渐变、pattern、NPOT shader 表达；样式票 |
| `src/features/{rect,image,path,text,clip,composite}/` | 各特性票各自拥有子目录；不得复制状态或资源管理 |
| `src/lifecycle/` | dispose/lost/restore/resize 的跨模块编排；生命周期票 |
| `test/harness/`, `test/fixtures/`, `test/report/` | 同环境双渲染、环境采集、评审产物；测试设施票 |
| `test/cases/<feature>/` | 特性票自带语义与差分用例；共享设施修改须交给设施负责人 |
| `test/cases/integration/` | 跨特性交互、完整支持矩阵核对；集成测试票 |
| `docs/acceptance/` | 游戏场景清单、证据格式、环境与评审模板；场景文档票 |
| 根 package/lock、导出表、类型声明、能力总清单、CI 配置 | 基础票集中建立；后续通过小的集成变更协调，禁止并发重复改写 |

内部接口变更需先在当前票说明受影响消费者，更新基础契约并通知相关票；在所有消费者更新前不将 blocker 标记完成。采用自动发现用例或各特性独立清单，避免多人争改一份测试注册表。

## 实施顺序与并发批次

1. **工程与契约**：先完成公共骨架和内部契约，再完成可独立验证的测试设施。测试设施用原生对原生的自检只能证明设施可用，报告必须注明不构成兼容实现验收。
2. **四条并行基础线**：绘图状态/context、GPU 设备/自动提交、原生路径光栅化、颜色/渐变/pattern。每条线有自己的代码与用例，按冻结的契约衔接；状态与 GPU 合并后，公开画布工厂票集中接线。
3. **第一条真实端到端链路**：矩形 API 连通 facade → 状态 → GPU → FBO → 自动上屏 → 测试读回，覆盖 strokeRect 辅助素材路径。它通过后才铺开其余绘制入口。
4. **并行特性线**：图像、路径填充描边、文字、合成/brightness、生命周期；裁剪接在路径入口完成之后。场景文档从工程基础完成后即可独立推进。
5. **汇合验收**：跨特性组合回归、完整支持矩阵核对、真实渲染对人工+AI评审，再执行 Web 七场景。
6. **延后平台票**：Web 证据齐备且调用方提供 vivo 运行环境/设备后执行。保持明确的 deferred 状态，不能由 agent 假造真机结果或自动承担平台接入工作。

GitHub 原生依赖记录的是“开始正式实施前需已合并的前置票”，不仅是口头先后顺序。跨阶段准备可只读进行；不能把尚未合并的分支 API 当成稳定接口。

## 测试分层与通过标准

| 层 | 内容 | 执行时机与结论 |
| --- | --- | --- |
| 纯逻辑与契约 | 矩阵、状态栈、路径记录、paint 更新、错误、队列与缓存不变量 | 每个相关变更；确定性断言可自动 pass/fail |
| 浏览器语义 | 原生合法/非法输入、绑定画布、转发、尺寸、身份、dispose、lost 行为 | 每个相关变更；真实 Canvas/WebGL，必要的平台故障用边界 adapter 注入 |
| 实际差分 | 同一脚本在原生与真实兼容实现运行；FBO和显示目标分别观察 | 每个绘制特性及组合变更；产出渲染对和辅助差异图，不预设分类/容差 |
| 交互回归 | 裁剪×合成×变换×alpha×filter、尺寸×排队、源更新×同帧多次取样等 | 汇合前全量；之后变更影响集 |
| 游戏场景 | 七场景人工步骤、公开 API 轨迹、未触发与矩阵外报告 | 首版全量一次；之后渲染/相关语义变更重跑受影响场景 |
| vivo 1200 | 平台能力和受影响功能/场景证据 | 调用方接入就绪后；独立于 Chromium 结果 |

每个特性票同时交付测试，不采用“所有实现完再补测试”。开发按公开行为执行失败用例→最小实现→通过，测试不镜像内部算法。矩阵内未被游戏触发的能力继续由单元/组合差分覆盖。

量化阈值尚不存在：`semantic: pass/fail`、`render: pending-review/accepted/rejected`、`execution: executed/blocked/not-run` 分开记录。任何 missing、skip、unsupported GPU、未执行场景或 pending-review 都不能汇总为兼容验收通过。AI 可给评审意见，不能填写人类已确认。特性票关闭前附该票新增/受影响渲染对的实际人工+AI评审记录；相关记录可在同一批次集中审阅，不要求每次开发迭代都打断用户。

测试设施至少交付这些命令或等价固定入口：`test:unit`（纯逻辑）、`test:browser`（语义+实际渲染对采集）、`test:report`（展示产物和评审状态）、`test:acceptance`（核对指定 run 的必需用例及人工评审完整性）。测试采集成功不等于 test:acceptance 成功；后者遇到缺评审必须返回明确未完成状态。没有 headless WebGL 时显式失败/阻塞，不自动换软件假实现冒充兼容渲染。

产物可复现：用例ID、版本/commit、运行ID、浏览器/GPU、DPR、字体、尺寸、输入/种子、原生图/实际图/差异图、错误、评审人/结论/日期。单元用例控制输入/种子；真实游戏不承诺随机种子，记录其随机源事实。报告工具用人工注入小块差异验证“差异可被定位”，不能把这些注入或代理渲染用作容差校准。

测试产物默认本地/CI artifact，不提交基线截图。游戏截图、轨迹、采集器、存档与游戏资源全部仓外存放；公开仓库仅保留清单、格式与环境记录模板。

## 每个实施票的完成门槛

- 明确对应规格条目与支持矩阵项，列出代码范围和不负责范围。
- 前置票已合并；实现和自带用例在同一工作分支完成，合并目标为 main。
- 附可重复命令、失败→通过证据与当前运行环境，不以私有方法 mock 代替真实浏览器组合验证。
- 新增/受影响像素用例有人工+AI评审；缺人类评审时保持开放并标记待评审。
- 无新公开 API、无隐式扩大支持集、无静默 fallback，无被遗漏的资源释放/失效路径。
- 通过 PR 评审并合并后才关闭票；最终集成票再核对完整矩阵，不能因各分支单测通过就宣布首版完成。

## 优先暴露的实现风险

- **source-in 的作用域**：只对源几何覆盖的片元调用 blend 并不足以证明 Canvas 语义。必须覆盖“已有目标 + 小源/透明源 + 裁剪”，验证有效裁剪内源外像素；保持 FBO+GL混合路线，先在合成票找正确的完整操作表达。
- **模板裁剪**：复杂路径来自原生光栅化，不能偷偷引入 CPU 三角化；凹形/挖洞/曲线与嵌套、模板位限制、AA边缘需在裁剪票验证。二值模板不能被直接宣称与原生软边一致。
- **任务/微任务提交**：同步 burst、rAF、Promise 链中追加绘制、resize/dispose/lost 发生在提交前均要测试。不能以“用了 queueMicrotask”证明已满足提交语义。
- **预绑定 GL 与默认帧缓冲**：严格检查实际 attributes、尺寸、stencil 能力；FBO跨帧保留与默认缓冲自动显示分别测试，不能用 preserveDrawingBuffer:true 避开已确认方案。
- **支持值与默认状态**：矩阵只列部分 setter 取值，但原生初始默认值可能不在列举值中；初始默认行为仍应正确，不能擅自改默认值。合法但超范围值显式不支持，非法值遵循原生语义，两者分开测试。

如果测试证明已批准路线无法满足规格，先提交可复现反例并新建决策票，将受影响实施票设为被其阻塞；不得自行换成双 FBO ping-pong、蒙版裁剪、整帧原生回退，或私设容差掩盖错误。不受影响的其他实施线可继续。

## 多 agent 领取约定

用户选择当前开放、无开放 blocker、无负责人且非 deferred 的票启动 agent。先认领（assignee + 评论注明 agent/分支/工作目录），一个票只允许一个 owner；每个 agent 用独立 worktree 和 `codex/` 分支。不共享写入 checkout，不创建新的用户聊天或自动派发 agent。

领取后阅读规格、ADR、本计划及票中前置产物；只修改本票归属路径。跨模块小修改由相应 owner 协调。合并顺序受依赖约束，合并前更新到 main 并重跑受影响测试；同一轮可开多个独立 PR，但不能通过修改支持矩阵或删用例来消除冲突。

下一批可领取项由 GitHub 的 sub-issues + 原生 dependencies 查询，不维护第二份容易过期的“ready”名单。
