# 七场景验收清单

落地票：[#25](https://github.com/shuizhongyueming/canvas2d-webgl/issues/25)。执行票：[#26](https://github.com/shuizhongyueming/canvas2d-webgl/issues/26)。场景清单与进入手段依据 [#8](https://github.com/shuizhongyueming/canvas2d-webgl/issues/8) 决策 8/9/10/12/13 及其事实基础。

每个场景的执行结果按 [evidence-format.md](evidence-format.md) 记录为一条场景运行记录；环境按 [environment-template.md](environment-template.md) 填写。标注「待核验」的条目表示 #8 未记录、本票也未执行的值，执行时以真实观察改写并注明来源；不得把本清单中的待核验项当作已验证事实引用。

## 通用前置（每场景执行前满足并记录）

- 环境记录填写完整；无法确认的字段填「待核验」。
- 游戏经任意静态服务器以 Web 入口 `src/index.html` 在桌面 Chromium 系浏览器运行（#8 事实：该入口可在桌面浏览器独立运行；Yandex/Poki SDK 缺失时自动降级 mock）。
- 字体：游戏唯一字体 `fonts/Montserrat-ExtraBold.ttf` 在启动前经 `document.fonts.load` 预载（#8 事实）；执行时以 `document.fonts.check` 记录实际加载结果，两条渲染路径使用同一已加载字体。
- 兼容画布接入与 API 轨迹采集器均从页面外部注入，不修改游戏任何文件；记录采集器标识与注入方式。
- 存档：`localStorage["stickmanfuryv4"]` 门控关卡、武器与解锁进度（#8 事实）。需要预设时经 devtools 写入并在场景记录中原样记录预设值；优先使用游戏内置重置（作弊键 3）。
- 随机源事实：游戏 `Math.random` 无种子机制（#8 事实：静态扫描 135 处）。不锁定种子、不承诺自动回放；每条场景记录附本次执行观察到的随机差异说明。

## SCN-01 loading 屏

- **目的**：验证启动与 loading 画面的兼容渲染，建立首个运行时轨迹段。
- **前置**：通用前置。无存档要求；如需已知起点，先作弊键 3 或 devtools 重置存档并记录。
- **进入步骤**：启动静态服务器；打开 `src/index.html`；页面外部注入采集器后加载游戏。
- **操作**：无输入，观察 loading 过程。
- **等待条件**：loading 完成并自动进入后续画面（#8 事实：无主菜单，splash 为瞬态）；记录实际等待到的画面状态。
- **证据点**：loading 期间 API 轨迹段；loading 画面参考/兼容截图对；字体加载检查结果。
- **备注**：本场景不预期 brightness 与动态源证据点；若轨迹中出现则在记录中说明。

## SCN-02 战斗主场景

- **目的**：覆盖主游戏循环的绘制组合；采集按钮悬停 brightness 证据。
- **前置**：通用前置；记录存档状态（关卡进度影响战斗内容）。
- **进入步骤**：接续 SCN-01 自动进入，或按存档进度进入战斗；记录实际进入路径。
- **操作**：按游戏内提示进行移动/攻击（具体键位待核验，执行时按游戏当前版本提示操作并记录实际操作序列）；悬停场景内可交互按钮触发 hover 效果；如需直接进入结算，用作弊键 2 杀光敌人。
- **等待条件**：战斗 HUD 与角色/敌人渲染稳定可见；悬停时按钮 hover 效果可见。
- **证据点**：
  - **brightness**：按钮悬停期间每帧触发 `filter: brightness(120%)`（#8 事实：`app.js:808`）；轨迹须含 `context.filter` setter 的 `brightness(120%)` 与 `none` 取值记录，并附对应帧参考/兼容截图对。
  - 战斗过程 API 轨迹段；随机差异说明（敌人行为等由无种子 `Math.random` 驱动）。
- **备注**：同帧逐取样点断言属 ACC-04 单元用例，不在本场景内逐帧断言（#8 决策 6）。

## SCN-03 customise 换装（含点色板换色）

- **目的**：覆盖动态源分支 A——同一外部 canvas 每帧修改后被反复取样。
- **前置**：通用前置；存档需达到可进入换装的进度（所需具体进度待核验，执行时记录预设值）。
- **进入步骤**：经游戏 UI 进入 customise 界面；具体入口控件待核验，执行时记录实际操作路径。
- **操作**：切换装备/武器项；点击色板更换颜色。
- **等待条件**：换装预览随操作更新；换色结果在预览中可见。
- **证据点**：
  - **动态源分支 A**：customiseTintCanvas 每帧 `clearRect` + `source-atop` 重染后作为 `drawImage` 源（#8 事实：`app.js:8612-8704`）；轨迹须显示该外部 canvas 源在场景内被反复取样（同一源多次 `drawImage`）。
  - 换色前后参考/兼容截图对。
- **备注**：游戏自建离屏 canvas 的内部原生调用不逐一计数，其正确性由本场景差分截图证明（#8 决策 3/6）。

## SCN-04 结算-进度条形态

- **目的**：覆盖动态源分支 B——每帧新建离屏 canvas 作为源；采集结算按钮 flash 的 brightness 证据。
- **前置**：通用前置；存档预设使当前武器 id < 23（#8 事实：该条件对应进度条形态）；优先作弊键 3 重置后按需 devtools 预设，预设值原样记录。
- **进入步骤**：进入战斗后用作弊键 2 杀光敌人结束战斗；记录实际触发结算的操作与跳转。
- **操作**：观察结算进度条动画；悬停结算按钮观察 flash。
- **等待条件**：结算界面出现且进度条动画播放；按钮 flash 可见。
- **证据点**：
  - **动态源分支 B**：进度条每帧新建离屏 canvas 并以 `source-in` 填色后作为 `drawImage` 源（#8 事实：`app.js:10318-10329`）；轨迹须显示该场景中 `drawImage` 的 native-canvas 源持续取样。
  - **brightness**：结算按钮 flash 期间 `filter: brightness(120%)` 轨迹与对应帧截图对。
  - 结算过程 API 轨迹段。

## SCN-05 结算-武器解锁形态

- **目的**：覆盖结算的另一形态（武器解锁展示）。
- **前置**：通用前置；存档预设使武器进度达到解锁形态。具体 id 阈值待核验（#8 仅记录武器 id<23 对应进度条形态）；可用作弊键 6 循环武器辅助达到目标进度；预设值与达成路径原样记录。
- **进入步骤**：同 SCN-04，作弊键 2 结束战斗进入结算。
- **操作**：观察武器解锁展示；与结算界面按钮交互。
- **等待条件**：武器解锁形态出现并完成展示。
- **证据点**：结算解锁形态 API 轨迹段；解锁画面参考/兼容截图对；按钮 flash 若发生则记录 brightness 轨迹。

## SCN-06 窗口缩放

- **目的**：提供 CAN-04 运行时证据——画布 `width`/`height` 设置的清屏与状态重置语义。
- **前置**：通用前置；先进入任一稳定场景（建议战斗）。
- **进入步骤**：记录缩放前窗口尺寸、DPR 与画布尺寸。
- **操作**：改变浏览器窗口尺寸（至少一次缩小或放大、一次恢复原始尺寸）；观察游戏是否设置画布 `width`/`height`（#8 决策 8 以本场景提供 CAN-04 运行时证据；游戏的具体响应行为待核验，执行时如实记录）。
- **等待条件**：缩放后布局稳定、画面重绘完成。
- **证据点**：`canvas.width`/`canvas.height` setter 轨迹（次数与取值）；缩放前后参考/兼容截图对；重置语义观察记录（像素清空与状态重置的可见表现）；跨屏拖动导致 DPR 变化时记录前后 DPR。

## SCN-07 上下文丢失/恢复

- **目的**：验证 LIFE-02/03——丢失时暂停并通知、丢失期绘制静默无效、恢复后重建资源、清屏并通知重绘。
- **前置**：通用前置；进入战斗场景并保持运行。
- **进入步骤**：经 devtools 在目标画布的 WebGL 上下文上取得 `WEBGL_lose_context` 扩展（#8 决策 5：用该扩展在游戏运行中主动触发丢失/恢复，不要求真机自然丢失）。
- **操作**：调用 `loseContext()`；丢失期间继续游戏操作并观察；随后调用 `restoreContext()`。
- **等待条件**：`onContextLost` 回调触发；恢复后 `onContextRestored` 回调触发，画面按契约清屏后由游戏重绘。
- **证据点**：回调记录（名称、次序、时间）；丢失期间绘制调用按原生 context-lost 语义静默无效（不抛错、不排队）的轨迹证据；**恢复重绘**画面参考/兼容截图对。

## 不纳入的场景

pause、credits、颜色解锁为不可达死代码（#8 事实），不纳入清单；游戏后续版本打通这些路径时再补场景（#8 决策 12）。

## 执行时机

首版宣称完成时全量执行一次；此后仅当渲染管线或场景相关语义变更时重跑受影响场景，不要求每次提交执行（#8 决策 13）。
